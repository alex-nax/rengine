# F184 (F150a) — the tool surface is data, captured rather than retyped (2026-09-13)

Spec 129, KI-100. The first third of F150; F185 carries the calls, F186 the live panes.

## The problem this row exists to avoid

`agents/mcp-worker.mjs` serves **38 tools**, and their descriptions are not documentation — they
are the surface. An agent reads them to decide what to call, and `tools/list` returns them verbatim,
so "responses identical to the JS worker's" means *byte-identical prose and schemas*. Fifteen
kilobytes of description retyped into Rust is a transcription error waiting to happen; nobody would
notice a dropped clause until a CLI made a wrong call because of it.

So the surface is **captured**, not retyped: a client connected to the running JS worker, asked for
`tools/list`, and the answer — with the server identity, instructions and capabilities — became
`red/red-mcp/src/tools.json`. red-mcp serves exactly that.

## What keeps it honest while both exist

`orchestrator/tests/red-mcp.test.mjs` starts **both** servers against one live workspace, drives
them with the same MCP client, and compares deeply: the tool list in order, every description,
schema and annotation, the server identity, the instructions a CLI reads on connect, and the
capabilities. While `mcp-worker.mjs` exists this is a live two-implementation comparison; when F185
deletes it, the declaration becomes the frozen record — the discipline F148, F172 and F178 all
ended up at.

red-mcp also checks its binding at startup the way the worker does: the context must name a
loopback host with a 64-hex token, the host must still be the instance the context names, and the
bound root must still exist. A pane whose workspace moved is told at once rather than on its first
tool call.

## Sabotages, each observed failing for its own reason

| Sabotage | Observed |
| --- | --- |
| a description in the declaration drifts by three words | the deep comparison fails on `workspace_info`'s description |
| the JS worker grows a tool (`list_moons`) without a recapture | `the same tools, in the same order` — `- 'list_moons'` against the captured list |
| (unit) a tool call is answered rather than refused | `-32601 … not implemented`, asserted in the crate |

The second is the one the row is for: a tool added on the JS side without recapturing leaves the
Rust side a version behind, and this is what makes that a red test rather than a silent gap.

## What red-mcp does not do yet

`tools/call` is refused by name with `-32601` and the reason. A server that answered a call
plausibly without being able to make it happen would be worse than one that says it cannot: F185
carries the calls, the native exec change, and the deletion of `mcp-worker.mjs` and
`runtime/tools.mjs`.

`red_core::http` now holds the one authenticated GET both red-link and red-mcp make, rather than
each crate keeping its own copy of the same forty lines.
