# Image preview qualification

The real Electron test decodes PNG, JPEG, GIF and WebP through the authenticated project API.
Two roots contain `image.png` with different pixels; rendered pixel assertions identify the
intended root before/after a verified tab move, refresh and GUI restart. Replacing a file with
header-only PNG data shows the browser decoder error; replacing it with a valid file and
refreshing recovers. No editor draft or working-file write is generated by previewing.

The service test rejects missing authentication, traversal, external symlinks, disguised markup,
truncated metadata, files over 8 MiB and oversized dimensions/pixel counts. It also checks the
actual returned bytes for both roots. Upstream metadata parsing uses pinned MIT-licensed
`image-dimensions` 2.5.1, with no transitive dependencies; npm reported zero vulnerabilities.

Commands on macOS 15.7.3 arm64 / Node 25.3.0 / Electron 44.2.0:

- `npm test`: 17/17 pass, about 4.4 seconds.
- `node --test orchestrator/tests/preview.spec.mjs`: pass, about 2.1 seconds after strengthening
  the pane-position check. The existing editor/terminal and real NOLF checks were also strengthened
  to assert movement into the target pane and rerun separately.

The first image acceptance run failed because the old UI opened PNG as text. The new pane fixes
that path. An additional check found the old drag gesture did not actually move tabs on this
Electron profile; intermediate pointer movements now generate a drop, and rendered bounds prove
the move. Neither the old gesture nor a surviving process alone is treated as move evidence.

The local screenshot `.cache/evidence/image-preview.png` was inspected; SHA-256
`627b40168877fe9e32bdabc908e1a169734d476322e1d682acaed75f9169a159`.
Windows, large-workspace resource budgets and remaining editor/draft failure cases remain open.
