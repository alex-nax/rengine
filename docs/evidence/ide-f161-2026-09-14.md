# F161 — Red as a Claude Code IDE, in Rust

2026-09-14. `orchestrator/runtime/ide.mjs` (199) and `agents/ide-connect.mjs` (76)
are thin clients now; `red/red-ide/` holds the lock the CLI reads, the socket that speaks MCP,
the startup sweep, the port retake, and the discovery that decides whether a pane's CLI is told
to connect. Spec 133 records the shape; this records what was measured.

## Why `ide-connect.mjs` came with it

F161's first criterion is "editor lock **discovery** honors `CLAUDE_CONFIG_DIR` and every distrust
rule of the evidence document on the ported fixtures". Discovery is `offeredEditors`: which locks
are read, which are believed, and which one is ours. Porting the bridge and leaving discovery in
JavaScript would leave the criterion's subject in JavaScript. It is still the caller's probe —
`agents-client.mjs` resolves it before asking `red-agents` for a plan, the owner's 2026-09-13
placement — and only the decision inside it is Rust, reached as `red-ide auto-connect`.

## The records

Two, taken from the JavaScript while it still answered, stable across three runs each, and then
frozen: the generators went with the implementation they asked, so neither can be regenerated
against its own replacement.

**`ide-corpus.json` — 20 cases, 174 steps.** Driven through a raw WebSocket client rather than the
SDK's, so every frame is recorded as the text that crossed the socket, key order included, and a
silence is recorded as a silence: a frame the SDK does not answer is followed by a `ping`, and the
ping's answer arriving first is the proof. The lock as written (mode, key order, escaping), the
four ways a host pid can be missing, the startup sweep on thirteen lock shapes, the MCP handshake and
thirteen silences, the SDK's own validation refusals in zod's sentences, `getDiagnostics` asked fourteen
ways from four kinds of source, the token gate in nine presentations, the subprotocol, fan-out,
close, the retake, the port never released, a successor closed while waiting, a slow source, a
directory that cannot be created, and the directory rule under eight environments.

**`ide-connect-corpus.json` — 13 cases, 38 asks.** Containment and the sibling, NFC, liveness on
nine pids, the lock's shape (seventeen files), the port read off the filename (`007`, `1e2`, `12.5`,
`-3`, `abc`), and every sentence `autoConnect` answers with, `undefined` for a nameless editor
included.

Folded: the port, the token, the temporary directory, this process's pid and its parent's, the
product's name, the `host` header. Not folded: the retake interval, every refusal, every reason.

## What the records found in the JavaScript, before it was replaced

Nothing wrong, and four things worth writing down that a reading of the code would have missed:

- A token followed by a space is **accepted**: HTTP trims trailing whitespace before the value is
  compared. A token presented twice is refused — Node joins the two with `, `.
- `Sec-WebSocket-Protocol: mcp, mcp` is a **400**, ws's own parser refusing a duplicate.
- A request whose `params` is `null`, a string, or an object whose `_meta` is not one is **not
  answered at all** — the SDK's request schema rejects it before any handler sees it — while
  `params: {}` on `initialize` is answered with three zod issues in a pretty-printed JSON message.
- `ide-connect.mjs`'s `living` counts `EPERM` as alive; `ide.mjs`'s sweep counts it as dead. Two
  rules, kept as two (spec 133 D5), and pid 1 is the recorded case for each.

## Parity, first pass

All 18 bridge cases were byte-identical on the first run against `red-ide serve`. Discovery
drifted once, and it was the record's catch: `fs.readdir` **sorts** — libuv's scandir does, on
every platform — and `std::fs::read_dir` answers in the filesystem's order. `lock::listing` sorts
by name now, for the sweep and for discovery alike.

**Two passed the first time, and each was a rule with no case.** S23 — the diagnostics call
awaited on the read loop, holding every later frame from that CLI behind a slow language server —
passed because every recorded step waits for its own answer. The case sends two frames at once
and records the order the answers come back in. S24 — a retake loop that ignores its own
retirement — passed because the record cannot see time: with the predecessor still holding the
port, the closed successor merely took ten seconds to fail on its deadline, and every answer was
the same. The case closes the successor and its predecessor **concurrently**, so the port frees
while the sabotaged loop is still running, and the difference is a lock on disk written by a
worker that had already retired. Both cases were added and the record regenerated while the
JavaScript still existed; the other cases came back byte-identical each time.

**One sabotage was itself wrong the first time.** The runner restored sources with `copytree`,
which keeps the backup's mtimes, and cargo took a restored file for an unchanged one: the binary
on disk after a run was the last sabotage's, and the next parity run went red for a sabotage that
had been "restored". The verdicts stood — each sabotage's own edit forced a full crate recompile
of the restored state plus that edit — but a restore is a change and is touched as one now.

## What the record cannot see, and what was done instead

- **`MutexGuard` across an `.await`.** Every socket is behind an unbounded channel and the map
  that holds them is locked for a clone and released, `red-host::events`' shape; the retake task
  and the connection tasks are taken out of the state under the lock and awaited after it.
- **Cost.** The reverse ask for diagnostics has no timeout, as the JavaScript's `await
  diagnosticsFor(uri)` had none; a worker that dies closes the pipe and the process exits. A
  connection task list is pruned on every accept rather than growing for the bridge's life. The
  close handshake waits are bounded at thirty seconds, ws's own close timer.
- **Key order.** `serde_json` with `preserve_order`, and every answer built in the SDK's order —
  the record compares text.
- **UTF-16.** No `String#length` bound exists in either module: the token is compared as bytes
  and the lock's fields are copied. Nothing to port.
- **Absent vs null vs empty string.** `hostPid` absent and `null` both refuse; `uri` absent and
  `null` are both the empty uri; `CLAUDE_CONFIG_DIR` set to `""` is the relative `ide` where unset
  is `~/.claude/ide`; `RENGINE_IDE_DIRECTORY` set to `""` is no override. All four recorded.
- **Node's error wording.** `EEXIST: file already exists, mkdir '<path>'` and `ENOTDIR: not a
  directory, mkdir '<path>'` are recorded and reproduced; a bind that fails for a reason other
  than the port being held is `listen EACCES: permission denied 127.0.0.1:80`, unit-tested.
- **What is machine-dependent in the record, stated:** pid 1 answers `EPERM` to a person and
  succeeds for root; `readdir` order is libuv's on every platform, so that one is not.

## What changed around it

- `runtime/worker.mjs`'s `/api/ide-selection` and `/api/ide-mention` routes `await` the delivered
  count (spec 133 D4, spec 132's precedent): a count that lives in another process is a round
  trip, and a client-side mirror would race the socket.
- `ide.test.mjs` and `ide-connect.test.mjs` name real pids where they used to pass an `alive`
  function: a function does not cross a socket. `observed` and `clients` are awaited.
- `ide-record.test.mjs` and `ide-connect-record.test.mjs` are deleted with the implementation they
  judged; their rule assertions live in the parity tests now, and the corpus modules keep the
  cases and the drivers but no longer know how to ask the JavaScript.
