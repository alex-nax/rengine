# F149 — the four JS agent modules are gone (2026-09-13)

The parent row of the agent half of the JS retirement (spec 129, charter D57). It was split into
three implementation rows and this document is the roll-up: each criterion names where it was
observed, and nothing here is claimed twice.

`orchestrator/agents/agents-client.mjs` is what stands in their place on the JS side: a thin client
with no decisions in it. The synchronous recipe surface is primed per document from
`red-agents dump`; `agentLaunch`, `agentIdentity`, `describeSession`, `bind` and `stateDirectories`
are JSON-RPC calls to `red-agents-serve`. That is the same shape `store-client.mjs` takes against
`red-store-serve`, which is deliberate: one transport pattern for the epic, not one per row.

## Criterion 1 — report-session is byte-identical for all five providers

`orchestrator/tests/red-report-session.test.mjs`, fourteen cases against
`report-session-fixtures.json` — the answers the JS CLI recorded **before** it was deleted, and
never regenerated since. All five providers appear: claude (both the rewrite and the
already-bound path), codex, kimi, and gemini and opencode, whose byte-identical answer is a
refusal by name. The noted-not-failed cases (malformed id, no id, nothing to report to, an
invalid connection, an unknown provider) are there too, because a hook that fails is a hook that
breaks the launch. Evidence: `docs/evidence/report-session-f172-2026-09-13.md`.

The port's own failure is recorded there rather than smoothed over: the Rust read its binding
before reading stdin, so a report with no binding consumed nothing and the writer blocked. The test
that caught it had to be rewritten to spawn the binary and assert observable effects, because the
original asserted on a return value the process boundary does not have.

## Criterion 2 — the codex hook key and trust hash match byte-exactly

`orchestrator/tests/red-agents-cli.test.mjs`, *"the codex hook key and trust hash are byte-exact
with the JS math"*: three command spellings (posix, quoted-with-spaces, win32) × two matchers,
each compared to the frozen JS answer, plus two pinned literals so that both sides drifting
together by edit still fails:

```
sha256:12f31cc1e970b72812fdbf48aad7d942ae48cbdf1293a490f430831b16651e2a   (default matcher)
sha256:8626ba99e1506308944b1ebc1f2dfcbcbb97057a8ff478807fba46080a38ed60   (startup)
```

The formula itself was verified against codex's own output, not only against the JS:
`docs/evidence/codex-sessionstart-hook-2026-09-11.md` records codex printing `sha256:01bab799…`
for a command and `hooks/list` reporting `trustStatus: "trusted"` when that hash was supplied —
and `"modified"` for a wrong one. So the criterion's chain is Rust = JS = codex.

## Criterion 3 — agent.sh's CLI is unchanged to its callers

Three separate observations, because they are three different claims — evidence:
`docs/evidence/red-agents-cli-f171-2026-09-12.md`.

- **The dispatch really is the binary.** `red-agents-cli.test.mjs`, *"agent.sh reads the registry
  through the binary, with node gone"*: `--action list` run with `RENGINE_NODE=/nonexistent/node`
  and a three-entry `PATH` answers with the five recipes, so node cannot be what answered. Pointing
  `RENGINE_RED_AGENTS` at a missing path names the binary in stderr rather than silently degrading.
- **The output is byte-exact.** *"list and show are byte-exact with the registry.mjs CLI, errors
  included"* compares `list`, `show` and `show-field` on the five shipped recipes plus one added
  through `RENGINE_AGENT_REGISTRY_EXTRA`, including the refusals (`No agent named nope is
  registered.`, `The registry has no NOPE for claude.`, usage exit 2), against what the JS CLI
  answered before deletion.
- **install/update/check-resume** are the pre-existing end-to-end runs in the suite, unchanged by
  this row and green; F171 recorded that they were not modified rather than re-proving them here.

## What this row does not claim

`agents-client.mjs`, `mcp.mjs`, `mcp-worker.mjs`, `launch.mjs`, `ide-connect.mjs` and `handoff.mjs`
are still JavaScript, and the server still runs on Node. F149 retires four modules named in its own
description; the rest of the epic is the rest of the epic. The owner's standing goal — no JS in the
app binary — is not met by this row and is not asserted here.
