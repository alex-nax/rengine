# F153 — task writes, prompts and the agent menu, in Rust

2026-09-14. `tasks.mjs` 194 → 79: a thin client of `red_project::tasks`, judged against 45 cases
recorded from the JavaScript.

## Why the wording is the interface here

Spec 083 refused task writes outright, because neither GitHub nor Linear offers concurrency control
on an issue write and a write from the workspace would be last-write-wins against a teammate's web
edit. Spec 103 decision 3 amended that for the **local** backend only, and only by running the
command the project itself declared: the workspace never edits an inventory.

So every refusal in this module is a boundary someone argued for, and an agent acts on the sentence:
"Nothing was attempted" means its inventory is untouched, and a command's own stderr means it is
not. `tasks-corpus.json` records all 45 answers word for word, and
`tasks-record.test.mjs` asserts that every pre-spawn refusal still ends in that sentence.

## Sabotages

Three, each observed failing for its own reason and restored:

1. a refusal that no longer says nothing was attempted → red
2. the action no longer written last, so a row carrying its own `action` renames the call → red
3. an unfilled *known* placeholder dropped rather than left in place → **passed first**

The third is the familiar shape: `promptValues` always supplies all five placeholders, so no case
in the corpus reached the branch. A template that silently lost `${criteria}` reads exactly like one
that never named it, which is the whole reason the misspelling case exists. One case was added and
the corpus re-recorded while `tasks.mjs` still answered; the 44 existing cases came back identical.

## The one thing that needed designing

The menu asks a CLI for its own model list — `codex --help` — but only when the project declares no
agents, and only when that CLI is installed. The JavaScript expressed that as three conditions
around a `help` function the caller passed in, and `task-writes.test.mjs` pins it by throwing from
that function: *a declared menu asks no CLI anything.*

Running a process is the caller's business; knowing **which** to run is this module's rule. So the
menu answers in two halves — what it can build now, and the CLIs whose `--help` it still wants — and
the client asks again with what it found. The rule stays in one place, and a client that guessed
would eventually guess differently from the menu it feeds.

## What stayed in JavaScript

- `listInstalled` and the `--help` run: a CLI is a process.
- `knownAgents` and `modelArgs`: read **synchronously** from the registry projection
  `agents-client.mjs` already holds, which is what a caller composing an argv needs. `red-project`
  holds the same two rules for the day the menu is answered there.

Five call sites gained an `await`, and one of them was a latent bug either way:
`promptFor(root, brief, promptValues(row))` in the worker passed a promise where a row's values
belonged.
