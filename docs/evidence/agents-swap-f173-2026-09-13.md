# F173 (F149c) — the consumers move to Rust, and registry/config/bind are deleted (2026-09-13)

Spec 129, KI-093. Two decisions were the owner's, taken before any of it was built:

- **The launch seam.** The DECISIONS move to Rust; the environment-dependent inputs stay with the
  caller. The root context, the workspace's session list and the IDE probe's answer arrive as JSON,
  so nothing in the crate opens a socket or scans for a lockfile. Chosen over porting the probing
  and the HTTP too, which is a later row's work and not this one's.
- **The transport.** A stdio service with a thin client, the shape red-store-serve established in
  F174 — not an exec per read, because `recipe()` sits on request paths in `tasks.mjs` and
  `worker.mjs`.

## What the seam had to make explicit

Three times the port failed because something had been *found* rather than *passed*, and each time
the fix was to name the input:

- **The extra registry document.** `red-agents-dump` takes it as `--extra`; a client that relied on
  the environment variable silently lost a recipe added as data.
- **The root context.** A caller that passed only `contextFile` got a null context and a refused
  launch, because the JS had read the file and the port had not.
- **The documents, per request.** A long-lived service reads the environment it was *spawned* with.
  One that had started while a test's extra document existed went on reading that path after the
  file was deleted. Every request now names the registry and the extra document it is about.

## Two things the port got wrong by being cleverer than the data

- **The id shape.** The registry declares each CLI's session-id pattern, and the first port read it
  by sniffing for substrings — which picked the ULID branch for kimi, whose ids accept a uuid *or* a
  ULID. The JS matched the pattern with a real engine, so the crate now does too (`regex`, pinned).
- **JSONC.** The opencode and gemini overlays read a person's own configuration, which is written
  with comments and trailing commas. A strict JSON reader refused a file that had always been
  accepted — and "existing configuration was preserved" is a refusal to launch, so the tolerance is
  load-bearing rather than a nicety.

## Parity, and what happens to a parity test when one side is deleted

`agents-fixtures.mjs` recorded what `registry.mjs` and `config.mjs` answered while they still
existed: the projection, the CLI's `list`/`show` output including its refusals, the conversation
parsers, the codex hook numbers, and a full launch plan for each of the five CLIs — args, consumed
flags, identity, and every per-launch file by content and by mode. **Regenerate it only from a
checkout where those modules exist, which is to say never again**: a regenerated record would be
judging the replacement against itself.

Three tests that had compared two implementations were re-based on that record rather than deleted,
because the claim survives even when one side does not: `red-agents-launch`, `red-agents-cli` and
`agent-registry-toml`. One assertion changed meaning rather than target — `typeof talk.parse ===
'function'` became a check that the recipe *declares* which parser reads its spellings, since
choosing a conversation from a CLI's own flags is a decision and decisions moved.

## Sabotages, each observed failing for its own reason

| Sabotage | Observed |
| --- | --- |
| the launch plan stops writing claude's settings file | `claude: the args the CLI is launched with` |
| the kimi project file keeps previous `rengine_` entries instead of replacing them | `a kimi launch wires the workspace MCP into the project it runs in, and nowhere else` |
| the client stops naming the documents per request | `a codex launch carries the SessionStart hook overlay beside its MCP wiring` |
| a dropped `--settings` flag (pre-deletion parity run) | `the args the CLI is launched with` |
| the trust hash computed for the wrong matcher | `the trust hash is the one codex will compute for the command this launch wrote` |

## The gates

`npm test` — **303 of 303**, with `orchestrator/agents/registry.mjs`, `config.mjs` and `bind.mjs`
deleted in the same commit, which is what c2 asks for. `cargo build -p red-agents` clean.

## What is still JS on the app's own path

`bind` is a Rust subcommand now, but `agents-client.mjs` and `mcp.mjs` remain: the client is the
thin surface this row created, and the MCP facade is its own retirement row. The goal — nothing JS
left in the shipping binary — is not met by F173 alone and this file does not claim it is.
