# F188 (F152a) — the front door, and the half-ported host problem (2026-09-13)

Spec 129, KI-101. The first half of F152, implemented **ahead of its parent's dependency** — see
*What this row does not claim* at the end.

## The problem the row had to solve first

`server/main.mjs` is 217 lines and a **dispatcher**: 33 `/api/*` routes plus the `/events` and
`/surface` upgrades, and most of those routes delegate to modules F153–F156 have not moved yet —
games, formats, dashboard, tracker, devices, recordings, images. There is one host process and one
port, so a Rust host that owned the port and answered only what it had ported would have to reach
back into JavaScript for most of a workspace.

**The answer is the shape the workspace already runs one layer up.** The root-bound worker fronts
the session host today and forwards `/api/*` to it (`runtime/protocol.mjs`'s `forward`/`tunnel`).
red-host does the same thing one layer down: it owns the port and the door, answers what it owns,
and forwards the rest to a JS backend beside it. Each later row moves routes across until the
forwarder has nothing to forward and the JS host is deleted.

## What the door owns today

The loopback bind, the descriptor (`sidecar.json`, tmp+rename, 0600, **its own token** — a client
never learns the backend's), `/health`, the origin rule and the bearer check. Two decisions in that
list are load-bearing:

- **Authentication is per request, not per connection.** A keep-alive connection carries many
  requests, and a door that checked only the first would be a door that stopped checking. Each
  request on a connection is read, checked and forwarded on its own.
- **An upgrade is spliced, not re-framed.** After the handshake the two sockets are copied byte for
  byte in both directions. A proxy that parsed WebSocket frames could corrupt a protocol it does
  not own; `/events` carries JSON and `/surface` carries binary game frames, and neither is this
  process's business.

Bodies are forwarded the way their own head framed them — by `Content-Length` or by chunks — for
the same reason.

## How "transparent" is judged

`orchestrator/tests/red-host.test.mjs` drives the same live host **directly and through the door**
and compares: six read routes answer the same status and the same body; a POST with a body reaches
the backend and the file on disk changes; the refusals are the JS host's own words and statuses
(`Workspace authentication required.` 401, `Origin is not this workspace.` 403); `/health` is the
door's own answer with its own instance; and a session attached over `/events` through the door gets
its `hello`, its `attached` snapshot, and — after the client sends input on that same socket — the
pane's output back.

## Sabotages, each observed failing for its own reason

| Sabotage | Observed |
| --- | --- |
| the door stops checking `/api/*` tokens | `404 !== 200` — with the check gone the path falls through to "unknown endpoint", and an unauthenticated request is answered by the door rather than forwarded |
| the client's socket token is passed upstream unchanged | `Unexpected server response: 401` — the backend refuses it, which is what makes the swap load-bearing |
| the upgrade is copied one way only | the attach never reaches the backend, and the frames that do arrive are the pane's own output |

The third one is the one worth keeping: with only the downstream half, `hello` and the pane's
startup output still arrive, so every assertion about *receiving* passes. What fails is that nothing
this client sends reaches the workspace.

## What this row does not claim

- **Nothing is deleted, and nothing in a running workspace uses this yet.** The four modules F152
  names are untouched; F189 carries the cutover and the deletion.
- **F152 is still blocked, and so this row is not flipped.** F152 depends on F150, and F150's last
  criterion is F186 — a live-pane run in the owner's workspace. That criterion is *verification of
  a capability that already exists in the boot path*, not a foundation this row needs, so the work
  was done rather than left idle; the row stays open until the evidence it asks for exists. If the
  owner would rather nothing in this lane moved until F186 lands, this commit is the one to revert.
