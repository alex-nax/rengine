# JavaScript's `.length` is UTF-16, and `chars().count()` is not

2026-09-14. Found while auditing what the declaration port (F156b) left behind, and fixed at six
sites across two crates.

## The rule

Every bound in this workspace was written against `String.prototype.length`, which counts **UTF-16
code units**. The obvious Rust spelling, `value.chars().count()`, counts **code points**. They agree
on every character below U+10000 and disagree by a factor of two above it.

So a port reads correctly, passes a corpus of ASCII fixtures, and quietly accepts twice the limit
its own message states:

```
envRules({ A: '😀'.repeat(2049) })   // ['env.A must be a literal string'] — 4098 code units
env_rules(…)                          //  accepted — 2049 code points
```

`red_core::text::utf16_len` and `truncate_utf16` are the spellings that mean what the rules say.

## The six sites

| where | bound | was |
|---|---|---|
| `red-project/src/rules.rs` `literal` | a declared env value, 4096 | `chars().count()` |
| `red-project/src/recordings.rs` | a recording index, 16 MiB | `chars().count()` |
| `red-project/src/recordings.rs` | the log-line budget accumulator | `chars().count()` |
| `red-mcp/src/tools.rs` | `preview_file` excerpt, 32000 | `chars().count()` |
| `red-mcp/src/tools.rs` | `preview_file` text truncation | `chars().take()` |
| `red-mcp/src/tools.rs` | the tree-depth retry budget | `chars().count()` |

The JS originals are in git: `orchestrator/server/recordings.mjs` used `text.length` for both of its
budgets, and `orchestrator/agents/mcp-worker.mjs` used `rest.text.length` and
`rest.text.slice(0, PREVIEW_BUDGET)`.

`truncate_utf16` differs from `String.prototype.slice` in exactly one way, and it is recorded in the
function: JavaScript would cut between the halves of a surrogate pair and keep the lone high
surrogate, which a Rust `String` cannot hold, so the pair is dropped and the result is one code unit
shorter. This is the same seam the PTY scrollback sits on from the other side (spec 060).

## Regression

The frozen declaration corpus cannot grow — it was recorded from the JavaScript while the JavaScript
existed — and every fixture in it is ASCII, so no case in it could ever have caught this. The
regression is a unit test at the site, `rules::tests::a_value_is_bounded_the_way_javascript_bounded_it`,
which names the JavaScript answer it mirrors. Sabotage: restoring `chars().count()` turns it red;
restoring the fix turns it green.

## The other way a rule hides: a NUL byte in a source file

The same audit tried to answer "who still imports `dashboard-rules.mjs`, `device-rules.mjs` and
`game-rules.mjs`?" and got a clean answer that was wrong. `orchestrator/server/games.mjs` imported
two of them — and the file contains a **literal NUL byte** in a template string:

```js
const key = `${rootId}<NUL>${config.id ?? ''}`;   // typed, not escaped
```

`grep -r`, `rg` and every tool that sniffs for binary content treat the whole file as binary and say
nothing about it. Deleting the three modules on the strength of that survey broke nine specs, which
is how it was found.

The string is identical written as `\0`; what differs is whether the file can be searched. A scan of
the checkout found exactly one such file, now fixed, and
`suite-coverage.test.mjs :: every owned source is text, so a search of the repository can see it`
asserts there is never another — sabotage-verified by putting the byte back.

That spec is the right home for it: its whole subject is things that become invisible in a green
report.

## What the three modules held, and where it went

`dashboard-rules.mjs` (59), `device-rules.mjs` (81) and `game-rules.mjs` (46) were duplicates from
the moment F156b ported the declaration reader: every function in them already exists in
`red-project/src/rules.rs`. Three live uses kept them alive, and all three are answered better:

- `formats.mjs` imported three of them and used **none** — dead since F156b.
- `runtime/scripts.mjs` validated a proposed script env with `envRules`; it now asks
  `red-project env-rules`, with the env on **stdin** because it is arbitrary caller input and argv
  has a length a caller could reach, and as a **field** of the request so an absent env and a null
  one stay different answers.
- `LOCAL` — the literal `'local'` — is `devices.mjs`'s own, which is the module a caller asks about
  devices; `games.mjs` keeps `PANE_SURFACES` beside the question it asks of it, with a note that it
  and the rule in `rules.rs` move together in F155.
- `integrate-project.test.mjs` re-validated the wizard's output with `dashboardRules`; it now reads
  the project back through red-project, which is the answer a person opening it would see.

Their ten sidecar entries moved to the code that holds the rules now — `rules.rs._llm.json` — rather
than being deleted with the files. Two more entries had been stranded on `formats.mjs` since F156b
(`bounded-report`, `pack-facets`) and moved to `rules.rs` and `declaration.rs`.

## And the constants the port stranded

The same audit, run over every export on the app path, found five definitions nothing references and
one duplicate that matters. `formats.mjs` still carried `CONTRACTS`, `ICON_TOKENS`,
`DEFAULT_TIMEOUT_MS` and `MAX_DECLARATION_BYTES`, plus three paragraphs of rationale with no code
left under them — all of it the declaration reader's, all of it in `red-project` since F156b.

`CONTRACTS` was the one that mattered: a hand-written `[1, …, 10]` that seven specs imported to say
"one above the ceiling", making a **third** statement of a fact the contract schema already declares
in `properties.contract.enum`. The specs read the schema now (`orchestrator/tests/contract.mjs`), so
a contract added to the document moves them without anyone remembering to, and
`declaration.rs`'s own constant — which the reader needs before the schema is parsed — is pinned to
the schema by a test rather than by habit.

The audit's other finding is worth stating because it is *not* actionable: thirty of the thirty-five
exports with no external consumer are used inside their own module, so they are over-exported rather
than dead. Narrowing them saves no lines and costs a thin client's stated API parity.
